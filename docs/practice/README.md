순서로 묶었다.

## 이 저장소가 강의 예제와 다른 전제

강의 예제(`jpashop`)와 이 서버는 성격이 정반대다. 아래 세 가지가 거의 모든 "다른 점"의
원인이라, 각 문서에서 반복해서 나온다.

**1. 쓰기가 없다.** 이 서버는 조회만 한다. 데이터 적재는 `tools/load_real_data.py`가
SQL로 직접 넣는다. 그래서 `persist`·변경 감지·`@Modifying`·`@Transactional`(쓰기)·
연관관계 편의 메서드가 코드에 한 줄도 없다. 서비스의 트랜잭션은 전부
`@Transactional(readOnly = true)`다.

**2. id를 서버가 만들지 않는다.** PK는 전부 원천 데이터(다비오 스튜디오)가 준 문자열이다.
`@GeneratedValue`가 하나도 없고 `Long id`도 없다.

**3. 스키마가 코드보다 먼저 있었다.** 파이썬 백엔드가 쓰던 PostgreSQL을 그대로 이어받는
이식이라, 엔티티가 스키마를 만드는 게 아니라 **스키마에 엔티티를 맞춘다**. `ddl-auto`는
`validate`이고 컬럼 이름은 파이썬 ORM 모델이 단일 출처다.
