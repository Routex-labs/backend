# 07. 자바 문법이 쓰인 자리

**대응 강의** — 자바 기본편 `6. 접근 제어자`, `8. final`, `12. 다형성과 설계`,
자바 중급편 1 `2. 불변 객체`, `5. 열거형 - ENUM`, `7~8. 중첩 클래스`

강의는 자바 8~11 문법으로 되어 있고 이 저장소는 **자바 17**이다. 그래서 강의에서 배운
개념이 **더 짧은 문법으로 실현된 자리**가 여럿이다.

---

## 1. record — `dto/` 40개 파일 중 39개가 record다

(나머지 하나는 `PlaceSection` — sealed interface, 3절.) 중첩까지 세면 저장소 전체에
record 선언이 62개다.

```java
public record LocalPoint(double x, double y) {}
public record CategoryCountResponse(String floor, String category, String subcategory, long count) {}
```

강의의 **불변 객체**(중급편 2장) 요구사항을 문법이 통째로 대신한다.

| 강의가 손으로 하라는 것 | record가 주는 것 |
|---|---|
| 모든 필드 `private final` | 자동 |
| 생성자에서 전부 초기화 | 정준 생성자 자동 |
| setter 금지 | 애초에 없음 |
| `equals`/`hashCode` | 자동 (값 동등성) |
| `toString` | 자동 |

이 저장소에서 record가 쓰이는 층은 셋이다.

**① 값 타입** — `LocalPoint(double x, double y)`, `LatLng(double lng, double lat)`,
`PointPair`, `GeoTransform`. 강의의 불변 객체 예제(`MyDate`)와 같은 성격이다.

**② 응답 DTO** — `dto/` 아래 전부. `equals`가 자동으로 생기는 게 테스트에서 유용하다.

**③ 설정** — `CacheProperties`, `CorsProperties`. → [05](05-스프링-컨테이너와-빈.md)

### compact 생성자 = 강의의 "생성자에서 검증하라"

```java
public CacheProperties(long tileMaxAge, long tileVersionedMaxAge, long glyphMaxAge) {
    tileMaxAge = tileMaxAge == 0 ? 60 : tileMaxAge;   // 파라미터를 고치면 필드에 그 값이 들어간다
    ...
}
```

record는 필드 초기화식을 못 쓰므로 기본값을 여기서 준다.

### 부생성자로 상수 필드 채우기

```java
public record HoursSection(String type, ..., String source) implements PlaceSection {

    public HoursSection(Map<String, List<Interval>> weekly, ...) {
        this("hours", weekly, ...);          // type을 부르는 쪽이 적지 않게 한다
    }
}
```

JSON의 `type` 판별자를 **레코드 자신이 상수로 들고 있다.** 부르는 쪽이 `"hours"`를 적으면
오타가 런타임에만 드러난다.

## 2. 중첩 record — 강의 7~8장(중첩 클래스)의 현대판

```java
// Floor 안
public record NonWalkablePolygon(String id, String kind,
        @JsonProperty("polygon_local_m") List<LocalPoint> polygonLocalM) {}

// TileService 안
private record TileKey(String buildingId, String floorName, int z, int x, int y, String revision) {}

// HoursSection 안
public record Interval(String open, String close) {}
public record Exception(String date, boolean closed, List<Interval> intervals, String note) {}
```

record는 **암묵적으로 `static` 중첩 클래스**다. 강의가 말하는 "내부 클래스는 바깥 인스턴스를
참조해 메모리 누수를 만들 수 있으니 `static`으로 두라"가 문법으로 강제된다.

`TileKey`가 특히 실용적이다. **캐시 키로 쓰려면 `equals`/`hashCode`가 필수**인데
record라 공짜다. 강의식으로 클래스를 쓰면 6필드짜리 `equals`/`hashCode`를 손으로 적거나
IDE 생성 코드를 유지해야 한다.

`HoursSection.Exception`은 이름이 `java.lang.Exception`과 겹치는데, 중첩이라
`HoursSection.Exception`으로 구분된다 — 다만 파일 안에서 `Exception`이 이 record를 뜻하게
되므로 읽을 때 주의가 필요한 이름이다.

## 3. sealed interface — 강의 12장(다형성과 설계)의 자바 17판

```java
public sealed interface PlaceSection
        permits HeroSection, NoticeSection, HoursSection, TagsSection, SummarySection,
                MenuSection, KeyValueSection, DemoInfoSection, LinksSection,
                BusinessInfoSection, MapSection {

    String type();
}
```

구현체를 **선언 시점에 못 박는다.** 얻는 것:

- 구현체 목록이 인터페이스 한 곳에 모인다. "섹션이 뭐뭐 있나"를 파일 하나로 안다.
- 컴파일러가 전부를 알고 있어 `switch` 패턴 매칭에서 **모든 경우를 다뤘는지 검사**해 준다
  (지금은 `switch`로 분기하는 코드가 없어서 쓰이진 않는다).
- 아무나 구현할 수 없다 — 상세 섹션은 순서가 서버 계약이라
  ([006 결정문서](../decisions/006-상세-섹션-순서.md)) 임의 구현이 끼면 안 된다.

record + sealed interface 조합은 **강의가 추상 클래스로 하던 것보다 훨씬 좁게 닫힌다.**

## 4. enum이 하나도 없다

`grep -rn "enum " src/main/java` → **0건.** 중급편 5장을 통째로 안 쓴 셈인데, 후보는 여럿
있었다.

```java
public final class PlaceKind {

    private PlaceKind() {}

    public static final String STORE = "store";
    public static final String FACILITY = "facility";
    public static final String EXCLUDED = "excluded";

    public static String of(String subcategory) { ... }
}
```

```java
// GraphService
public static final Set<String> VERTICAL_POLICIES = Set.of("auto", "elevator", "escalator");
```

### 왜 enum이 아닌가

**이 값들이 곧 JSON 문자열이자 API 계약이기 때문이다.** enum으로 만들면 응답 직렬화
(`@JsonValue`나 `EnumType.STRING`)와 역직렬화(`@JsonCreator`) 배선이 붙고, 그 배선이
문자열과 enum 사이를 오가는 지점이 하나 더 생긴다. 파이썬 응답과 **한 글자도 다르면 안
되는** 이식에서는 변환 계층이 하나 없는 쪽이 안전하다.

`transferMode`(`"elevator"`/`"escalator"`/`null`), `Poi.type`, `Node.type`도 마찬가지로
문자열이다. 이쪽은 이유가 더 강하다 — **원천 데이터가 어떤 값을 줄지 서버가 통제하지
못한다.** enum이면 모르는 값 하나에 적재가 통째로 실패한다.

### 대가

- 오타가 컴파일에 안 잡힌다. `"elavator"`를 적어도 빌드는 통과한다.
- `switch`에서 완전성 검사를 못 받는다. `GraphService.verticalAllows`가 `default`로
  떨어지는 게 그 예다.

**중급편 5장의 결론("타입 안전 열거형을 쓰라")과 정반대로 간 자리**이므로, 지금까지 이걸로
안 깨진 이유는 값 목록이 짧고 `PlaceKind`·`VERTICAL_POLICIES`가 단일 출처라서다. 값이
늘어나면 먼저 흔들릴 결정이다.

## 5. 정적 유틸 클래스 — 강의 6장(접근 제어자) 그대로

```java
public final class PlaceKind {
    private PlaceKind() {}
    ...
}
```

`final class` + `private` 생성자 = **상속도 인스턴스화도 막는다.** 강의의 유틸리티 클래스
관례 그대로다. `HttpCache`, `SharedPolygons`, `MvtWriter`, `TileBounds`, `AffineFit`,
`PlaceMapper`, `BuildingGeoTransforms`(는 빈)가 이 형태다.

빈으로 만들지 않은 기준은 [05](05-스프링-컨테이너와-빈.md) 7절에 있다.

## 6. Optional — 쓰는 자리를 규칙으로 정해 뒀다

```java
// 서비스: 없으면 빈 Optional
public Optional<BuildingDetailResponse> detail(String buildingId) {
    return buildingRepository.findById(buildingId).map(this::toDetail);
}

// 컨트롤러: HTTP 상태로 바꾼다
return buildingService.detail(buildingId)
        .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "Building not found"));
```

**규칙: 반환값에만 쓴다.** 필드·파라미터에 `Optional`이 있는 곳이 없다. 서비스 주석마다
"없는 건물이면 빈 Optional. HTTP 상태 변환은 컨트롤러가 한다"가 반복해서 적혀 있다.

체이닝이 실제 규칙을 표현한 예:

```java
// BuildingService.defaultFloor — 지상 최저층, 없으면 최상층, 그것도 없으면 null
return floors.stream()
        .filter(floor -> floor.getLevel() >= 1)
        .min(Comparator.comparingInt(Floor::getLevel))
        .or(() -> floors.stream().max(Comparator.comparingInt(Floor::getLevel)))   // 폴백
        .map(Floor::getName)
        .orElse(null);
```

`or()`는 자바 9에 들어온 것이라 강의 예제에는 없다. `if`로 쓰면 세 갈래인 규칙이 한
표현식으로 읽힌다.

```java
// PlaceDetailService — 다른 건물 매장이면 없는 것으로 취급
return storeRepository.findById(placeId)
        .filter(store -> store.getFloor() != null
                && store.getFloor().getBuilding().getId().equals(buildingId))
        .map(store -> toDetail(buildingId, store));
```

`filter` 하나로 **권한 비슷한 검사**를 표현했다. 조건이 맞지 않으면 404가 되는데,
"없다"와 "남의 것이다"를 같은 응답으로 만드는 게 의도다.

## 7. 불변 컬렉션

```java
List.of()          // 빈 목록 — null 대신
List.copyOf(actions)   // 방어적 복사 후 반환
.toList()          // 스트림 → 불변 리스트 (자바 16+)
```

`.collect(Collectors.toList())`가 아니라 `.toList()`를 쓴다. **결과가 불변**이라는 게 차이다.

```java
// PlaceDetailService.actions — 조립은 가변으로, 반환은 불변으로
List<PlaceActionResponse> actions = new ArrayList<>();
if (store.getEntranceNodeId() != null) { actions.add(...); }
if (!PlaceKind.EXCLUDED.equals(kind))  { actions.add(...); }
return List.copyOf(actions);
```

조건부로 넣어야 해서 `ArrayList`로 만들지만, **밖으로 나갈 때 닫는다.** 강의 중급편 2장의
"불변 객체를 반환하라"를 컬렉션에 적용한 형태다.

### null 대신 빈 값

```java
// StoreRow.facet — 미태깅 매장이 대다수라 빈 맵이 정상이다
public List<String> facet(String axis) {
    if (searchFacets == null) return List.of();
    List<String> values = searchFacets.get(axis);
    return values == null ? List.of() : values;
}
```

DB에서 온 jsonb가 null일 수 있어 **두 겹으로 방어**한다. 부르는 쪽에 null 검사가 퍼지지
않게 하는 게 목적이다.

## 8. switch 표현식 (자바 14+)

```java
static boolean verticalAllows(String policy, String transferMode) {
    if (transferMode == null) return true;                 // 층 내부 간선은 항상 포함
    return switch (policy) {
        case "elevator", "escalator" -> policy.equals(transferMode);
        default -> true;
    };
}
```

- `break`가 없다 — fall-through 사고가 구조적으로 불가능하다.
- `case "a", "b" ->`로 라벨을 묶는다.
- **표현식**이라 `return`이 하나다.

강의(자바 8 기준)의 `switch` 문과 비교하면 이 메서드가 강의식으로는 6~8줄이다.

## 9. 텍스트 블록 (자바 15+)

```java
@Query("""
        select s.id, s.name, f.id, f.name, s.category, s.subcategory, s.entranceNodeId
          from Store s join s.floor f
         where f.building.id = :buildingId
         order by f.level desc, s.id
        """)
```

강의 시점에는 `"select ... " + "from ... "` 연결이었다. **끝에 공백을 빠뜨려 단어가 붙는
사고**가 사라진다.

주의: 닫는 `"""`의 들여쓰기가 **공통 여백의 기준**이다. 위 예에서 `select`가 왼쪽 정렬로
보이는 건 그 규칙 덕이다.

## 10. 그 밖에

**`instanceof` 패턴 매칭 (자바 16+)**

```java
return bean instanceof DataSource dataSource ? new P6DataSource(dataSource) : bean;
```

캐스팅 한 줄이 사라졌다.

**정적 임포트 (테스트)**

```java
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.assertj.core.api.Assertions.assertThat;
```

테스트에만 쓴다. 운영 코드에는 정적 임포트가 없다 — 어느 클래스의 메서드인지가 안 보이면
읽기가 나빠져서다.

**`Comparator` 조합**

```java
building.getFloors().stream()
        .sorted(Comparator.comparingInt(Floor::getLevel).reversed())
        .toList();
```

`comparingInt`는 박싱을 피하는 쪽이다(`comparing`은 `Integer`로 박싱한다). 층 수십 개
규모에서 성능 차이는 없지만, 기본형 특화 메서드가 있으면 그쪽을 쓰는 게 습관으로 낫다.

## 정리

| 강의 개념 | 자바 17에서 실현된 방법 |
|---|---|
| 불변 객체 (중급 2장) | `record` |
| 정적 중첩 클래스 (중급 7~8장) | 중첩 `record` (암묵적 static) |
| 다형성과 설계 (기본 12장) | `sealed interface` + record |
| 열거형 (중급 5장) | **안 씀** — 문자열 상수 + 유틸 클래스 (이유는 4절) |
| 접근 제어자 (기본 6장) | `final class` + `private` 생성자 |
| `final` (기본 8장) | 모든 주입 필드, record 필드 |
| `Optional` | 반환값 전용 규칙, `or()`·`filter()` 체이닝 |
