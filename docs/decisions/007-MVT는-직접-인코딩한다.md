# 007. MVT 바이트를 직접 인코딩한다

## 결정

JVM용 MVT 라이브러리를 쓰지 않고 `MvtWriter`로 직접 protobuf를 쓴다(약 190줄, 의존성 0).

## 버린 안

**`com.wdtinc:mapbox-vector-tile:3.1.0`** — JVM에서 사실상 유일한 실용 후보다. 버린 이유:

- 최신 릴리스가 2019년이고 이후 관리가 없다.
- JTS를 전이 의존으로 끌고 온다. 우리는 지오메트리 연산을 하지 않고 좌표를 그대로 쓴다.
- 필요한 것은 스펙의 일부(Point/Polygon, 문자열·불리언·숫자 속성)뿐이다.

라이브러리 하나를 더 얹어 얻는 것보다 200줄을 읽을 수 있게 두는 편이 낫다고 판단했다.

## 어떻게 검증했나

바이트가 스펙에 맞는지는 자바만으로 확인할 수 없다. **파이썬 `mapbox_vector_tile`로 디코드해서**
확인했다 — 원본 저장소가 인코딩에 쓰는 바로 그 라이브러리다.

`TileControllerTest.servesTileBytes`가 타일을 `build/tile-dump.mvt`로 떨구고, 그 파일을 디코드하면
레이어 5개(footprint·stores·non_walkable·store_labels·pois)가 extent 4096 / version 2로 나오고
한글 속성과 `shared` 표시까지 그대로 읽힌다.

## 좌표 규약

MVT 스펙 그대로 **왼쪽 위 원점, y는 아래로 증가**다. 파이썬 인코더가 같은 규약을 쓰는지는
직접 인코딩해 원시 정수를 뜯어 확인했다(파이썬 *디코더*는 읽을 때 y를 뒤집어 돌려주므로,
디코드 결과만 보면 규약을 알 수 없다).

## 남은 차이

| | 파이썬 | 자바 |
|---|---|---|
| ETag 해시 | blake2b-128 | SHA-256 앞 16바이트 |
| 리비전 원천 | SQLite 파일의 (경로, mtime) | 타일 입력 컬럼 md5 |

ETag는 불투명 값이라 알고리즘이 달라도 계약이 유지된다. 리비전은
[008](008-타일-리비전은-입력-해시.md) 참고.
