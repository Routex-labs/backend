## 옮기면서 바꾼 것

**좌표 타입을 엔티티와 DTO가 공유한다.** 파이썬은 ORM(JSON 컬럼)과 Pydantic 모델이 따로였지만
`{"x":…,"y":…}`로 모양이 같고 갈라질 이유가 없어 `LocalPoint` 하나로 뒀다.

**상세 응답이 요약을 상속하지 않는다.** 자바 레코드는 상속이 없다. JSON은 어차피 평평해야 하므로
필드를 그대로 다시 적었다.

**섹션 판별자는 레코드의 첫 컴포넌트다.** Jackson 다형 설정을 걸지 않았다 — 이 응답은
내려보내기만 하고 되읽지 않는다.

**오버레이를 기동 시 한 번만 읽는다.** 파이썬은 요청마다 디렉터리를 다시 읽는다. 이 파일들은
배포 산출물 안에 있어 프로세스가 사는 동안 바뀌지 않는다.

**해시 알고리즘이 다르다.**

| | 파이썬 | 자바 | 왜 무방한가 |
|---|---|---|---|
| 그래프 리비전 | blake2b-128 | SHA-256 앞 16바이트 | 클라이언트에게 불투명한 캐시 키 |
| 타일 ETag | blake2b-128 | SHA-256 앞 16바이트 | 같음 |

JDK에 blake2b가 없다. 두 값 모두 "같으면 같고 다르면 다르다"만 지키면 되는 불투명 값이다.

**타일 리비전의 원천이 다르다.** 파이썬은 SQLite 파일의 `(경로, mtime)`, 자바는 타일 입력 컬럼의
md5다. PostgreSQL에는 파일 세대가 없다 — [008](../decisions/008-타일-리비전은-입력-해시.md).

**MVT를 직접 인코딩한다.** 파이썬은 `mapbox_vector_tile`을 쓰고 자바는 `MvtWriter`가 직접 쓴다.
바이트가 맞는지는 파이썬 디코더로 확인했다 — [007](../decisions/007-MVT는-직접-인코딩한다.md).

## 옮기지 않은 것

| 파이썬 | 왜 |
|---|---|
| `dto/place_detail.py` `ChildListSection` | 선언만 있고 어떤 조회 경로도 만들지 않는다. 죽은 코드라 옮기지 않았다 |
| `repositories/place_details.py` 검증 함수들 | API 경로가 아니라 시드·검증 스크립트가 쓴다. 오버레이 작성 도구가 파이썬에 남아 있는 한 그쪽이 단일 출처다 |
| `repositories/store_facets.py` (546줄) | **질의 경로가 import하지 않는다.** `scripts/seed/studio_adapter.py`만 쓴다 — 태그는 시드 시점에 `stores.search_facets` 컬럼으로 구워지고, 매칭은 구워진 값만 읽는다. 시드 도구가 파이썬에 남아 있는 한 옮길 이유가 없다 |
| `geo/georeference.py` `compose_transforms` | 현재 어느 경로도 두 변환을 합성하지 않는다. 필요해지면 그때 옮긴다 |
